## Detailed findings

### [P2] 1. Rich-text lead and card action labels use the wrong roles

- **Location:** `app/views/packages/index.html.erb:13`; `app/frontend/entrypoints/application.css:647`; `app/views/packages/_card.html.erb:66` and `:81`.
- **Category:** Theming / Implementation integrity.
- **Evidence:** The introduction wrapper declares `text-t4`, but its inner `.trix-content` declares `text-t5`, which wins. `trix-copy` changes line height only. Consequently the lead is 16px/500 rather than 19px/400. The details button explicitly uses `text-t5`, while its adjacent booking button uses `text-t6!`.
- **Impact:** The page feels typographically different from home/about, and the secondary action is visually louder than the primary action. The introduction also loses the intended lead/body distinction.
- **Standard:** DESIGN.md’s Lead, Body, and Label roles. Font size alone is not a WCAG AA violation.
- **Recommendation:** Apply a lead modifier that styles the actual rich-text child and preserves the intended supporting color. Normalize comparable card action labels to the existing Label role while retaining generous target heights. Verify stored rich content and the plain-text subtitle fallback.
- **Suggested command:** `$impeccable typeset /packages`.

### [P2] 2. Three columns start before cards have enough reading width

- **Location:** `app/views/packages/index.html.erb:22`.
- **Category:** Responsive design.
- **Evidence:** Three published packages switch to `md:grid-cols-3` at 768px. At that width, measured action/content widths are approximately 171px; package names span two or three lines and body sentences become long narrow columns. The details action grows to about 77px high because its label wraps.
- **Impact:** Tablet visitors must scroll through tall, fragmented text, making side-by-side package comparison harder. There is no horizontal overflow; this is a usable-width problem.
- **Standard:** PRODUCT.md’s phone-first reading requirement and DESIGN.md’s reading hierarchy; no confirmed WCAG failure.
- **Recommendation:** Keep fewer columns through the tablet range and enter three columns only when the actual card content has adequate width. Check 640–1024px, including the uneven final row with three packages.
- **Suggested command:** `$impeccable adapt /packages`.

### [P2] 3. The comparison relies on a tiny raster table

- **Location:** `app/views/packages/index.html.erb:34`; `app/helpers/packages_helper.rb:38`.
- **Category:** Accessibility / Responsive design.
- **Evidence:** The current 1800px-wide comparison upload is rendered at 640px on desktop and 350px on a 390px phone. Its short alt text identifies the comparison but does not express its rows, columns, or included/not-included markers. The image contains its own fonts, colors, and small footnotes. Zooming makes text larger but requires panning across columns and row labels.
- **Impact:** A visitor cannot scan the comparison comfortably on a phone or customize its typography. Screen-reader users must reconstruct the comparison from separate package details.
- **Standard:** [W3C complex-image guidance](https://www.w3.org/WAI/tutorials/images/complex/) recommends a text equivalent for detailed information. [WCAG 1.4.5 guidance](https://www.w3.org/WAI/WCAG21/Understanding/images-of-text.html) allows an image when the same information is also presented as text. Because package dialogs already provide substantial text equivalents, this audit does **not** assert a blanket 1.4.5 failure without a complete cell-by-cell content parity check.
- **Recommendation:** Provide an accessible semantic comparison from the owner’s existing package facts, with readable mobile presentation. Keep the uploaded artwork as optional supplementary content if desired. Verify every row and exclusion against published content; do not invent benefits or rewrite factual claims.
- **Suggested command:** `$impeccable adapt /packages`.

### [P2] 4. Unavailable-calendar copy offers contact without an immediate action

- **Location:** `app/views/bookings/_calendar.html.erb:38`, `:44`, `:98`.
- **Category:** Implementation integrity / Accessibility.
- **Evidence:** The local availability integration returned an unavailable state. The notice says to retry or write for a direct appointment, but contains no contact link. The disabled calendar and “pick a day” instruction remain visible. By contrast, the separate no-slots state already provides an Instagram action. The error notice also uses 14px Label typography for a full recovery sentence.
- **Impact:** The next step is unclear precisely when booking cannot proceed; the visitor must locate the contact action in another section.
- **Standard:** PRODUCT.md’s truthful unavailable states and 16px reading-copy role. This is an observed fallback defect, not evidence that production availability is broken.
- **Recommendation:** Reuse the existing contact action inside the unavailable notice, set its prose as Body, and suppress or replace inert selection instructions. Preserve a clear retry path.
- **Suggested command:** `$impeccable harden /packages`.

### [P2] 5. Comparison thumbnail reserves no image geometry

- **Location:** `app/components/lightbox/component/item_component.html.erb:4`; `app/helpers/packages_helper.rb:44`.
- **Category:** Performance / Responsive design.
- **Evidence:** The thumbnail `<img>` has no `width`, `height`, or reserved aspect ratio. Dimensions passed by the packages view become PhotoSwipe data attributes on the link, not intrinsic image dimensions. It is lazy-loaded. The legacy embedded-upload path uses the full image as both source and thumbnail; the dedicated image field does generate an 800×1100-limited variant.
- **Impact:** Before a cold lazy load finishes, the comparison can collapse and then push the calendar down. The legacy path also loads a larger image than its inline display requires.
- **Standard:** Image geometry and responsive image optimization; layout-shift risk confirmed by markup, actual CLS not measured.
- **Recommendation:** Reserve the thumbnail’s true aspect ratio using its known dimensions and use an appropriate thumbnail variant for the embedded path as well. Keep the full source for zoom.
- **Suggested command:** `$impeccable optimize /packages`.

### [P2] 6. Every page eagerly loads the shared controller graph

- **Location:** `app/frontend/controllers/index.js:4`; `app/frontend/controllers/lightbox_controller.js:2`.
- **Category:** Performance.
- **Evidence:** The controller registry uses `import.meta.glob(..., { eager: true })`; PhotoSwipe and its CSS are imported at controller-module load. The current production-style test build’s application JS is **611,944 bytes raw / 169,259 bytes gzip** (Ruby Zlib default compression). This is a shared entrypoint, not a packages-only payload measurement.
- **Impact:** A passive mobile visitor downloads and parses UI code before using the comparison lightbox, including controllers irrelevant to the route.
- **Standard:** Route/interaction-based code splitting. No measured claim about LCP or INP.
- **Recommendation:** Load PhotoSwipe on first comparison interaction and examine controller registration for safe lazy loading. Preserve Stimulus/Turbo behavior and privacy commitments.
- **Suggested command:** `$impeccable optimize /packages`.

### [P2] 7. Calendar controls fall below the product’s thumb target

- **Location:** `app/frontend/entrypoints/application.css:448`, `:520`.
- **Category:** Responsive design.
- **Evidence:** At a 320px viewport, calendar previous/next controls measure 40×40px and day cells measure 36×36px. Day cells were disabled in this inspected unavailable state; the same geometry applies to enabled days when availability exists. Package actions and modal close controls are generously sized.
- **Impact:** Dense calendar navigation is less forgiving for a tired parent using one hand.
- **Standard:** DESIGN.md/PRODUCT.md’s thumb-sized controls and the audit’s 44px usability target. **44px is not a WCAG 2.1 AA requirement**; this finding is not labelled an AA failure.
- **Recommendation:** Increase navigation hit areas and choose a calendar layout/gutter strategy that improves day targets at the narrowest supported widths. Do not create overlapping hit regions or horizontal page scrolling.
- **Suggested command:** `$impeccable adapt /packages`.

### [P2] 8. Custom comparison zoom bypasses reduced-motion options

- **Location:** `app/frontend/controllers/lightbox_controller.js:277`.
- **Category:** Accessibility.
- **Evidence:** PhotoSwipe’s installed implementation turns off opening/closing animation and sets `zoomAnimationDuration = 0` under reduced motion. The custom image-click handler instead passes a fixed `333` milliseconds directly into `slide.zoomTo`, bypassing that option.
- **Impact:** Image clicks can still animate spatial zoom for visitors who requested reduced motion. The built-in Zoom button and opening transition already respect the library option.
- **Standard:** Reduced-motion preference; related [WCAG 2.1 SC 2.3.3](https://www.w3.org/WAI/WCAG21/Understanding/animation-from-interactions.html) is AAA, not AA. Verified in source; an OS-level reduced-motion browser run was not performed.
- **Recommendation:** Pass the library’s resolved zoom duration or an explicit reduced-motion branch into the custom handler, preserving the zoom state change instantly.
- **Suggested command:** `$impeccable harden /packages`.

### [P3] 9. Polish comparison controls retain English labels

- **Location:** `app/frontend/controllers/lightbox_controller.js:531`.
- **Category:** Implementation integrity / Theming.
- **Evidence:** On the Polish route, the lightbox exposes buttons named “Zoom” and “Close”. The custom zoom percentage indicator uses a system font rather than Quicksand. Core package dialogs correctly use Polish labels.
- **Impact:** Small language and type discontinuities appear in the comparison interaction, including screen-reader control names.
- **Standard:** Existing locale-aware UI and DESIGN.md’s two-font system. No conformance failure asserted for these short UI terms.
- **Recommendation:** Provide locale-derived PhotoSwipe control titles and use the existing Label font token for its custom indicator.
- **Suggested command:** `$impeccable harden /packages`, followed by `$impeccable polish /packages`.

## Systemic patterns

- Parent typography classes cannot override an explicitly styled `.trix-content` child. Rich-text containers need role-aware modifiers, verified against rendered content rather than class names alone.
- Shared primitives inherit defects across routes: calendar sizing, lightbox geometry, and eager controller imports should be fixed in their shared implementation with checks on other consumers.
- CMS-uploaded comparison artwork is independent of current package data and design tokens. A text equivalent also makes stale rows easier to detect.

## Positive findings

- No document horizontal overflow at 320, 390, 768, or 1440px.
- Package details use native dialogs with meaningful names, package-specific action labels, and an independently scrolling reading region.
- Keyboard opening focuses the heading; Tab reaches Close, reverse Tab wraps to the booking action, and Escape closes and restores focus to the correct opener.
- The mobile dialog fits the viewport: 358px wide × 812px high inside a 390×844 viewport.
- Card actions align at the bottom despite differing copy lengths. Heading, title, body, and closing-lead sizes otherwise match the shared scale.
- Prices come from the price service; missing prices remove the booking action and expose a truthful contact fallback in source.
- Comparison thumbnails are lazy-loaded; the dedicated-upload path already creates a smaller variant.
- Empty testimonials are omitted, and the palette and self-hosted fonts preserve the incumbent identity.
